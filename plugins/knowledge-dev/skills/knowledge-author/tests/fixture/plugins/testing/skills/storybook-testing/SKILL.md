# Storybook testing

Write stories with interaction tests for one React component. This file is the workflow. The rules
it applies are in the index below; each row links to the full rule with an incorrect and a correct
example.

## Workflow

1. **Read the component**: props, callbacks, conditional rendering, every state it can show, and
   anything it renders into a portal.
2. **Plan the stories**: one story per distinct state (different args mean a different story).
   Write the plan as a numbered comment at the top of the file.
3. **Get the data**: reuse a builder (`*.builder.ts`) for typed props; if none exists, run
   `/builder-factory` first.
4. **Write the file** next to the component as `<component>.stories.tsx`.
5. **Add the tests**: one `.test()` per independent behaviour, grouped as the rules below say.
6. **Run** `npm run test:storybook -- --grep "<Component>"`. Read each failure, fix, re-run.

## Rules

Open a rule's file when the step you are on touches it. `critical` rules apply to every file you
write.

## Before you write

- Which interactions, validation rules and keyboard paths must be covered?
- Which states exist (loading, error, empty, success), and which need their own story?
- What needs mocking: callbacks (`fn()`), network (MSW), modules (`sb.mock()`), context
  (decorators), data (builders)?
- Does anything render in a portal?
