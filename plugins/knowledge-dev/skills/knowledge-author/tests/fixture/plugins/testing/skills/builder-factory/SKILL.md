# Builder factory

Create or extend a test data builder for one type or model. The workflow is the same in every
language; the rules differ by library, so read only the rows for the project's language.

## Workflow

1. **Detect the stack.** `package.json` with `mimicry-js` → TypeScript rows. `pyproject.toml` or
   `requirements*.txt` with `factory-boy` → Python rows. Neither → ask which to use.
2. **Reuse first.** Search for existing builders (`**/*.builder.ts`) or factories
   (`**/factories.py`, `**/factories/*.py`) and extend one before creating another.
3. **Read the type or model**: fields, optional fields, enums, nested types, relations.
4. **Write the builder** next to the feature's tests, named after the type (`userBuilder` in
   `user.builder.ts`, `UserFactory` in `factories.py`).
5. **Show one usage** in the test that needed it, with explicit values for everything it asserts.

## Rules

Rows marked `any` apply in every language. Skip rows for the language this project does not use.
