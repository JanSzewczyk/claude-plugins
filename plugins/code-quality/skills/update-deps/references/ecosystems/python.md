# Python profile

> **Status: beta, to be tested.** These commands were checked against each tool's documentation but have not been run end-to-end. If one fails or behaves differently than described here, say so in the report instead of quietly working around it.

Covers uv, Poetry, PDM, Pipenv, pip-tools and plain pip.

## Tool detection

Take the first match, per project directory:

| Signal                                                                                 | Tool      |
| -------------------------------------------------------------------------------------- | --------- |
| `uv.lock`                                                                              | uv        |
| `poetry.lock`, or `[tool.poetry]` in `pyproject.toml`                                  | Poetry    |
| `pdm.lock`                                                                             | PDM       |
| `Pipfile.lock` or `Pipfile`                                                            | Pipenv    |
| `requirements*.in`, or a `requirements*.txt` headed "autogenerated by pip-compile"     | pip-tools |
| `requirements*.txt`, `setup.py`, `setup.cfg`, or `[project]` in `pyproject.toml` alone | pip       |

Run everything inside the project's environment (`uv run`, `poetry run`, `pdm run`, `pipenv run`, or an activated virtualenv). **Never install into the global interpreter.** If pip or pip-tools has no virtualenv to use, ask where it lives instead of creating or guessing one.

## Verification

Use what the project already configures, found in `pyproject.toml`, `tox.ini`, `noxfile.py`, `Makefile` and CI workflows. A project's own wrapper (`make test`, `tox`, `nox`) wins over the raw tool.

| Check      | Look for                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| Type-check | `mypy`, `pyright`, only if configured                                                                        |
| Lint       | `ruff check`, `flake8`, `pylint`, only if configured                                                         |
| Build      | `uv build`, `poetry build`, `pdm build`, or `python -m build`, only when `pyproject.toml` has `[build-system]`. An application with no build backend records this as "not available" |
| Tests      | `pytest`, `tox`, `nox`. These don't watch by default, so nothing needs disabling                             |

## Outdated

| Tool             | Command                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| uv               | `uv pip list --outdated --format=json`, after `uv sync`                                                       |
| Poetry           | `poetry show --outdated --top-level --format json`                                                            |
| PDM              | `pdm outdated` (PDM 2.13+, table output)                                                                      |
| Pipenv           | `pipenv update --outdated`                                                                                    |
| pip-tools, pip   | `pip list --outdated --format=json`                                                                           |

Listings from uv and pip include transitive packages. Keep only the direct dependencies, meaning those the manifest declares (`pyproject.toml`, `requirements*.in`, `requirements*.txt`, `Pipfile`). Transitive packages move through the lockfile as a side effect.

Python versions are PEP 440, not always semver. `2024.1` is calendar versioning, and `1.0a1`, `1.0b2`, `1.0rc1` and `1.0.dev1` are pre-releases.

## Apply

Keep the existing constraint style (`^`, `~=`, `>=,<`, `==`) and the dependency's group or extra. "Within" means the new version already fits the declared constraint; "outside" means the constraint has to change.

| Tool      | Within the constraint                       | Outside the constraint                                        | Then            |
| --------- | ------------------------------------------- | ------------------------------------------------------------- | --------------- |
| uv        | `uv lock --upgrade-package <pkg>`           | `uv add "<pkg>>=<ver>" --upgrade-package <pkg>`, with `--dev`, `--group <g>` or `--optional <extra>` as needed | `uv sync`       |
| Poetry    | `poetry update <pkg> …`                     | `poetry add <pkg>@latest`, with `--group <g>` as needed. This writes a caret range, so use `poetry add <pkg>==<ver>` for an exact pin | `poetry sync`   |
| PDM       | `pdm update <pkg> …`                        | `pdm update --unconstrained <pkg> …`                          | `pdm sync`      |
| Pipenv    | `pipenv update <pkg>`                       | edit `Pipfile`, then `pipenv lock`                            | `pipenv sync --dev` |
| pip-tools | `pip-compile --upgrade-package <pkg> <in>`  | edit the `.in` file, then the same `pip-compile` command      | `pip-sync <txt>` |
| pip       | edit the pinned line                        | edit the pinned line                                          | `pip install -r <file>` |

`poetry sync` needs Poetry 2. On older versions, use `poetry install --sync`.

## Rollback

```bash
git checkout -- <manifest> <lockfile>
```

Restore every file the group changed (`pyproject.toml`, `uv.lock`, `poetry.lock`, `pdm.lock`, `Pipfile`, `Pipfile.lock`, `requirements*`), then run the tool's sync command from the Apply table so the environment matches again.

## Audit

Use `pip-audit` against a fully pinned requirements file, so the result doesn't depend on which environment `pip-audit` runs in. Plain `pip-audit` audits its own environment, which is wrong when it runs from `uvx` or `pipx`.

1. Get a pinned file. pip-tools and pinned pip projects already have one. Otherwise export to the scratch directory, not the repo:
   - uv: `uv export --format requirements-txt --no-hashes -o <tmp>`
   - PDM: `pdm export --no-hashes -o <tmp>`
   - Poetry: `poetry export -f requirements.txt --without-hashes -o <tmp>`, which needs `poetry-plugin-export`
   - Pipenv: `pipenv requirements > <tmp>`
2. Audit it: `pip-audit -r <tmp> --no-deps --disable-pip -f json`. Each finding lists `fix_versions`.
3. If `pip-audit` isn't available, run it ephemerally through `uvx pip-audit` or `pipx run pip-audit`, and say so. If neither exists, or the export fails, try `osv-scanner scan source -r --format json .`, which reads `uv.lock`, `poetry.lock`, `pdm.lock`, `Pipfile.lock` and `requirements.txt`. If that isn't available either, record "audit unavailable" in the report.

**Severity:** `pip-audit` output has no severity field. Report the count of advisories and look up the severity of each from its ID (`osv-scanner` output carries it) only when that changes a decision.

**Auto-fix:** a `fix_versions` entry that fits the current constraint needs no confirmation: apply it with the "within the constraint" command. Anything outside goes through the breaking path in SKILL.md. Avoid `pip-audit --fix` on compiled or lock-based projects, since it doesn't know about those files.

## Edge cases

- **`requires-python`**: a new release can drop support for the project's Python. That is a blocker to report, not a reason to change the Python version.
- **Compiled wheels** (`numpy`, `psycopg`, `cryptography`): a resolver or build failure often means no wheel exists for this platform and Python, not a code problem. Report it that way.
- **Multiple requirements files** (`requirements-dev.txt`, `constraints.txt`): keep a package on the same version in all of them.
- **Hashed requirements**: `--hash` lines must be regenerated, never hand-edited.
- **Private indexes**: leave the index configuration alone, and record packages the tool can't reach.
