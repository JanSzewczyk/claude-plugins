# React Compiler

The rules for memoization and hooks are in the `react-rules` knowledge skill. This skill is the
procedure: turn the compiler on, check it works, and migrate a module off hand-written memoization.
The full reasoning is in the adoption guide linked from the index below.

## Enable

1. Check the setup in the project's own docs first (`next.config.*`, `package.json`, the lint
   config), then confirm the current option names with Context7 (`react.dev/learn/react-compiler`,
   Next.js `reactCompiler`): they changed between Next.js 15 and 16.
2. Install `babel-plugin-react-compiler` as a dev dependency and set `reactCompiler: true` at the top
   level of `next.config.ts` (Next.js 16; `experimental.reactCompiler` before). Outside Next.js, add
   the Babel plugin first in the plugin list.
3. Lint with the `recommended` preset of `eslint-plugin-react-hooks`; remove
   `eslint-plugin-react-compiler` if present.

## Verify it is active

Open a component in React DevTools: compiled components show a `Memo ✨` badge. In a production build
the output imports `react/compiler-runtime`. A component without the badge breaks the Rules of
Hooks or React; run the lint rules on it and fix the code, not the rule.

## Migrate a module

1. Run the lint rules over the module and fix what they report.
2. Delete `useMemo`, `useCallback` and `memo` that only existed for performance, one module at a
   time, and run the module's tests after each.
3. Keep a memoization only for the four cases in `react-rules`, each with a JSDoc comment saying why.
4. Before adding memoization back, profile with the React DevTools Profiler or `<React.Profiler>`; a
   render under about 16 ms needs none.
